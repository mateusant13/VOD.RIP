### Why `I:` and not `G:` or `H:`

`git worktree move` is **same-drive-only**. All 42 registered VOD.RIP worktrees
were on `I:`. A root on `G:` or `H:` would not merely be slower - it would make
the whole migration impossible, because git refuses a cross-drive move outright.
So the root shares `I:` with the trees being moved. `archive/` is a sibling of
the other three states, so it is on the same drive as the root for free, which is
the entire reason that state exists.

Free space, measured now: C: 13.4 GB - G: 29.2 GB - H: 77.1 GB - I: 47.6 GB.

### This moved nothing across drives, so it freed no space

**Bytes reclaimed: 0.** The 1323 MB measured across these lanes
(1.29 GiB total) sits on exactly the same drive as before. A move
inside one drive is a rename. If the goal is storage, this change is not it:
reclaiming space means moving trees to `H:` (102 GB free), which cannot be done
with `git worktree move` and is therefore a separate, riskier decision.

## The three commands

Create a lane (the destination is resolved from the manifest, never typed):
```
scripts/wt-new.sh --project vod-rip --lane my-lane            # -> I:/vod-rip-wt/wip/my-lane
scripts/wt-new.sh --project vod-rip --lane my-lane --state done
```

```
scripts/wt-restore.sh --lane wt-ar        # -> I:/TEMP/wt-ar

Undo the entire migration (safe to run twice; it converges):
```
scripts/wt-restore.sh --all
